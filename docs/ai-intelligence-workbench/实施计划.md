# AI 情报工作台实施计划

## 文档依据与约束

实施以《产品需求文档》确定业务结果，以《产品原型》及 `原型/index.html` 确定视觉和交互，以《研发方案设计》确定数据、接口、错误码、日志和验收。本文只规定交付顺序和质量门禁；三份设计文档与本文冲突时，停止实现并按产品需求文档、产品原型、研发方案设计的顺序处理。

采用 pnpm workspace、Vue 3 + TypeScript + Element Plus、Node.js 22 + Fastify + Zod + better-sqlite3 + node:test。服务保持单进程；SQLite 启用 WAL、外键和 FTS5；AnySearch 通过 REST 接入；LLM 使用 OpenAI-compatible Chat Completions。不得新增 Redis、PostgreSQL、向量数据库或独立 Worker。

## 交付顺序

1. C01 工程骨架、幂等 SQLite 迁移、统一数字错误码/日志/响应、`GET /api/system/health`，并验证 17 张表、FTS5 和迁移重复执行。
2. C02 来源库：初始化 30 个来源，完成 `GET/POST/PATCH /api/sources`、SSRF 防护、来源页面和新增/停用弹窗。
3. C03 扫描：完成 `POST/GET /api/scans`、详情、重试和 SSE，含状态机、幂等、恢复、今日扫描交互。
4. C04 采集：接入 RSS/API/网页采集和 AnySearch，保存搜索溯源及原始发现，完成 `GET /api/discoveries`。
5. C05 分析：实现去重、FTS5 候选、Jaccard 聚类、六维评分、证据冲突和 `GET /api/signals`、详情。
6. C06 生成：实现模型结构化校验、降级摘要、机会/选题/趋势实体及对应列表和详情接口。
7. C07 反馈：实现收藏、忽略、价值反馈、归档、机会/选题状态和实体关注。
8. C08 前端：按原型补齐浅色导航、所有页面、加载/空/失败/部分失败状态、Element Plus 弹窗及三种视口。
9. C09 使用真实 SQLite、AnySearch、公开来源和 LLM 执行 BT-001 至 BT-005 及 E2E-001；只有业务验收通过才可宣告完成。

每个阶段完成必要单元测试、全量接口测试、类型检查和构建后立即形成一个独立提交。提交信息必须包含 description、root cause、solution 三段中文内容。发现设计契约冲突、FTS5 不可用、接口 case 未通过、日志无法定位或需要设计外基础设施时，停止后续实现。

## 接口测试门禁

每个接口开发时在 `server/tests/api/` 编写完整 case。测试通过生产迁移入口创建隔离 SQLite，使用 Fastify `inject`；不得 Mock 路由、Repository 或数据库。AnySearch/LLM 的确定性协议失败可用本地 HTTP 测试服务模拟，BT/E2E 必须使用真实服务。

所有 JSON 接口共同断言 HTTP 状态、六位业务码、固定消息、`details`、`requestId`、camelCase 响应、数据库副作用、幂等结果和结构化日志，且错误中不得泄漏 SQL、堆栈、密钥、正文或完整 prompt。请求体接口必须覆盖缺字段、类型错误、非法 JSON、错误 Content-Type；正整数 ID 覆盖 0、负数、小数和非数字；分页覆盖默认、1、100、越界、空页、下一页及非法 cursor。

- `POST /api/scans`：四种范围、30 天边界、新建/幂等/活动复用，以及 200001、200002、200003、200004、100001、100004。
- `GET /api/scans`、详情、重试、SSE：全部任务状态、分页、步骤明细、续跑、SSE 快照/进度/心跳/重连/终态，以及 200005 至 200009、100001、100002、100004。
- `GET /api/discoveries`：每项筛选、组合筛选、分页、正文不出现在列表，以及 300001、200005、100002。
- `GET /api/signals`、详情、状态更新：搜索、筛选、排序、证据详情、归档幂等，以及 400001 至 400004、200005、100002。
- `PUT /api/item-states`：三种目标、字段组合、幂等和 450001 至 450003。
- 机会、选题、实体的列表/详情/状态或关注接口：全部合法枚举、分页、幂等与 500001 至 500003、600001 至 600003、700001 至 700002、100001、100002。
- 来源接口：列表筛选、启停保护、三种来源类型、URL 规范化；覆盖 800001 至 800007，包括 localhost、私网 IPv4/IPv6、链路本地、云元数据、DNS/重定向 SSRF、重复和不可达地址。
- 健康检查：数据库、FTS5、活动任务和版本正常态，及 100004、900001 异常态。

每完成一个接口先运行目标文件，再运行 `pnpm test:api`；任何失败或 skipped 禁止提交。领域完成后运行 `pnpm typecheck` 和 `pnpm build`。

## 日志与验收

HTTP/SSE 使用 LOG-001 至 LOG-004；任务使用 LOG-101 至 LOG-110；采集使用 LOG-201 至 LOG-205；分析使用 LOG-301 至 LOG-305；模型使用 LOG-401 至 LOG-404；用户状态与来源使用 LOG-501 至 LOG-507；启动和健康使用 LOG-601 至 LOG-604。所有关键日志包含 requestId，适用时包含 taskId、sourceId、signalId 和 businessCode。

最终验收从 Web 的“今日扫描”入口执行：发起 24 小时扫描、观察 SSE、浏览和检索结果、核查证据、打开机会或选题、收藏、关注趋势、刷新恢复，并在 1440px、1024px、390px 对照原型。另覆盖来源超时、AnySearch 配额耗尽、模型超时/Schema 失败、SSE 断开、重复点击和服务重启恢复。

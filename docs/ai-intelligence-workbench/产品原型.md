# AI 情报工作台产品原型

## 1. 原型信息

- 需求简称：`ai-intelligence-workbench`
- 原型入口：[原型/index.html](./原型/index.html)
- 原型状态：v0.3 可切换工作台高保真静态原型
- 对应需求：[产品需求文档.md](./产品需求文档.md)

本原型用于验证单人 Web 工作台的主链路和菜单级交互，不代表最终视觉规范或技术实现。原型可以直接在浏览器打开，所有页面内容使用静态示例数据。

## 2. 设计目标

原型优先验证四件事：

1. 用户能否一眼理解并手动触发一次扫描；
2. 用户能否在大量结果中先看重点，再进入完整情报流；
3. 用户能否区分普通情报、副业机会和内容选题；
4. 用户能否看到主题持续变化，而不是每次只读一批孤立新闻。

## 3. 页面结构

### 3.1 全局导航

左侧导航改为浅色工作台风格，使用低对比度背景、青绿色选中态和细边框，避免深色侧栏压低长时间阅读的可读性。导航分为两组：

- 工作台：今日扫描、完整情报流、趋势追踪、副业机会、内容选题；
- 资料库：收藏、扫描历史、来源库。

每个菜单都可以在原型中切换到独立视图；首版默认进入“今日扫描”，因为它是所有情报任务的真实起点。

菜单交互范围：

- **今日扫描**：时间范围选择、开始扫描、进度状态、重点信号、趋势摘要、机会/选题入口；
- **完整情报流**：关键词搜索、主题筛选、价值/时间/证据排序选择、情报详情弹层、收藏；
- **趋势追踪**：主题指标、时间线、关注/取消关注主题；
- **副业机会**：按全部/建议验证/已验证/已收藏筛选，查看机会详情和验证动作；
- **内容选题**：按平台筛选，查看平台适配角度和选题详情；
- **收藏**：查看已收藏的情报、机会卡和选题卡；
- **扫描历史**：按任务状态筛选，查看历史扫描结果或失败原因提示；
- **来源库**：按来源类型筛选，开关来源组，查看自动发现候选和新增来源入口。

### 3.2 今日扫描页

页面由以下区域组成：

- 顶部标题区：说明当前日期、产品任务和主要价值；
- 扫描控制区：选择过去 24 小时、3 天、7 天或自定义范围，并点击“开始扫描”；
- 扫描状态区：展示任务状态、进度条、已发现数量和主题数量；
- 概览指标：本次发现、去重后信号、机会卡、选题卡；
- 重点信号：按价值排序展示高优先级情报；
- 趋势追踪：展示用户关注主题的近期变化；
- 扫描动态：展示本次任务的关键节点和新发现；
- 可继续判断的结果：突出展示副业机会卡和内容选题卡。

### 3.3 其他工作台页面

其他页面共用相同的顶栏、卡片和状态组件，页面状态不跳出当前 HTML 原型：

- 列表类页面通过筛选按钮和搜索框即时更新内容；
- 详情类页面使用居中的详情弹层，提供事实、证据、下一步和状态操作；
- 状态变更用按钮文本、标签或轻提示反馈，不依赖页面刷新；
- 关注主题和来源组开关会更新当前页面状态；
- 页面之间可以通过顶部操作、卡片底部动作和侧栏互相跳转。

### 3.4 情报卡层级

情报卡采用“先判断、再深入”的结构：

- 第一层：来源、时间、价值分、标题和一句话结论；
- 第二层：技术/业务变化、标签、证据数量和适用结果类型；
- 第三层：收藏、查看分析、原始证据和后续状态。

重点信号不会覆盖完整情报流。首页只改变阅读顺序，不删除其他发现。

## 4. 核心交互状态

### 4.1 扫描任务

用户点击“开始扫描”后，系统进入异步任务状态：

```text
待开始 -> 发现中 -> 去重与聚类中 -> 分析中 -> 已完成
                                      ├-> 部分失败
                                      └-> 失败
```

原型中通过按钮点击模拟状态变化：

- `扫描中`：状态文字变为琥珀色，进度条从 18% 开始；
- `去重、聚类和证据核查`：进度推进到 54%；
- `生成机会卡和选题卡`：进度推进到 82%；
- `已完成`：进度到 100%，更新发现数量，并出现完成提示。

### 4.2 情报反馈

- 点击“收藏”后按钮变为“已收藏”，并出现轻量提示；
- 点击“查看分析”进入详情面板（本轮原型仅以提示占位）；
- 查看完整情报流、历史和全部卡片的入口已经放置，但不在本轮展开页面。

v0.3 已将以上入口补为可切换视图，详情入口打开真实的原型弹层，并补充扫描、来源管理、忽略与归档的弹窗反馈；数据仍为静态示例。

### 4.3 趋势追踪

右侧趋势面板展示关注主题的信号数量和变化方向。主题时间线的完整页面不在本轮展开，但入口和状态已经在信息架构中固定。

### 4.4 弹窗与操作反馈

原型补充以下反馈层级：

- 点击“开始扫描”先显示确认弹窗，明确本次扫描时间范围和国内/国际搜索区域；确认后才创建任务；
- 扫描完成后显示结果汇总弹窗，并可直接进入完整情报流；
- 扫描历史中的“部分失败”可以打开失败详情，展示已保留结果、错误码 `300005`、请求 ID 和重试入口；
- 情报详情支持“忽略”和“归档”确认，避免误操作；
- 关闭来源组前显示确认弹窗，启用来源组使用轻提示；
- “添加来源”打开完整表单弹窗，展示字段级校验位置；
- 收藏、关注、状态更新和筛选成功使用 Toast，不中断当前操作；
- 阻断错误弹窗显示六位业务错误码和请求 ID，不显示堆栈或内部异常。

同一时刻只显示一个模态弹窗。弹窗支持关闭按钮、点击遮罩关闭和 Esc 关闭；阻断弹窗必须由明确操作关闭。

## 5. 视觉与组件约定

- 采用浅色工作台背景和浅色侧栏，强调长时间阅读的可读性；
- 使用青绿色表示可行动和已完成，琥珀色表示处理中或需要验证，珊瑚色表示趋势变化和内容机会；
- 卡片圆角控制在 8～12px，避免营销页面式的大圆角和装饰性背景；
- 按钮只承载明确动作，状态通过标签、进度条和颜色表达；
- 重点信息采用密度适中的列表卡，而不是大面积 Hero 或装饰卡片；
- 移动端保留内容顺序：标题 → 扫描控制 → 指标 → 重点信号 → 趋势和机会卡。

## 6. 主链路验收观察点

使用原型时重点观察：

- 是否能在首次进入页面时理解“系统要做什么”；
- 扫描按钮是否是页面最明确的主操作；
- 结果数量较多时，重点信号、完整情报流和原始发现库的层级是否清楚；
- 机会卡和选题卡是否与普通情报卡有足够差异；
- 价值分、证据数量和来源信息是否能帮助用户相信或质疑一条信号；
- 趋势追踪是否让用户感受到“持续观察”，而不是一次性的新闻列表。

## 7. 原型边界

本轮原型不包含真实采集、登录、后端任务、全文证据展开、主题时间线详情、卡片编辑、导出和移动端专属页面。这些能力会在研发方案中根据主链路拆分实现。
